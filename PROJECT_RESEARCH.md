Дата фиксации: 21 ноября 2026 года.

## 1. Решение по движку

**Основной стек: Unity 6.3 LTS + C# + URP.**

В проекте закреплена версия Unity Editor **6000.3.28f1**. Unity 6.3 — актуальная LTS-линейка на момент выбора; LTS предпочтительна для долгого проекта, потому что получает исправления и поддерживается дольше обычных update-релизов. Версия 6000.3.28f1 выбрана как конкретная воспроизводимая точка сборки; перед обновлением версии нужно проверить доступность соответствующего образа GameCI.

## 2. Почему URP, а не HDRP

Для Android выбран **Universal Render Pipeline 17.3.0**. URP поддерживает Android и позволяет масштабировать качество под разные GPU. HDRP не является подходящим мобильным рендер-пайплайном для этой цели.

Официальная совместимость Android и render pipeline:
https://docs.unity.cn/6000.3/Documentation/Manual/android-requirements-and-compatibility.html

Unity 6.3 поддерживает Android API 25 и выше, target API 35/36, Vulkan и OpenGL ES 3.x. URP совместим с Android, HDRP — нет. В build script выбран min API 26 и target API 36; это нужно перепроверить при фактической сборке на выбранной версии Unity/Android SDK.

В первом URP asset уже задан осторожный Android-профиль: HDR выключен, render scale 0.9, MSAA 2x, тени до 60 м и одна cascade, дополнительные источники света ограничены нулём, depth/opaque textures выключены, SRP Batcher включён. Статичная геометрия тестового города помечается для batching и occlusion. Эти параметры — стартовая конфигурация, а не подтверждённый FPS.

План графических профилей:
- Low: render scale 0.75–0.85, минимальные тени, короткая дальность прорисовки, простые эффекты.
- Medium: render scale около 0.9, одна каскадная тень от солнца, LOD и упрощённые отражения.
- High: render scale 1.0, повышенное качество материалов, теней и постобработки для мощных устройств.

Стартовый ориентир — стабильные 30 FPS на среднем телефоне; 60 FPS рассматривается как режим для устройств с запасом GPU/CPU. Это целевые показатели, а не уже измеренный результат. Настройки URP нужно профилировать на реальном устройстве: снижение render scale, отключение HDR/лишних проходов и ограничение теней могут улучшать производительность, но эффект зависит от конкретного GPU.

Официальные рекомендации Unity по URP:
- https://docs.unity.cn/6000.3/Documentation/Manual/urp/optimize-for-better-performance.html
- https://docs.unity.cn/Manual/urp/configure-for-better-performance.html
- https://docs.unity.cn/Packages/com.unity.render-pipelines.universal@17.3/api/UnityEngine.Rendering.Universal.UniversalRenderPipelineAsset.html

## 3. Физика автомобиля

Базовая модель использует четыре Unity WheelCollider и Rigidbody. WheelCollider моделирует контакт колеса с поверхностью, подвеску через spring/damper и продольное/поперечное сцепление через slip-based friction curves. Он не является полноценной симуляцией деформируемой шины и требует настройки под массу, привод, геометрию и скорость автомобиля.

Официальные материалы:
- Wheel colliders introduction: https://docs.unity.cn/6000.0/Documentation/Manual/wheel-colliders-introduction.html
- WheelCollider API: https://docs.unity.cn/6000.7/Documentation/ScriptReference/WheelCollider.html

Что необходимо довести:
1. Измерить реальные размеры импортированной машины и поставить WheelCollider точно в центры колёс.
2. Настроить массу, центр тяжести, подвеску, стабилизаторы и распределение тормозных усилий.
3. Настроить кривые сцепления для асфальта, мокрой дороги и грунта.
4. Добавить ABS/TCS как игровые системы помощи, если они нужны выбранному режиму.
5. Отдельно сделать упрощённые collision meshes для зданий, бордюров и ограждений.
6. Проверять поведение при торможении, повороте, заносе, прыжке и столкновении.

Важное ограничение: WheelCollider использует собственную модель трения и не следует автоматически стандартным Physics Material поверхности. Разные покрытия нужно обрабатывать настройкой forwardFriction и sidewaysFriction.

## 4. Город и производительность

Нельзя строить большой открытый город как один неограниченный набор детализированных объектов. Город нужно разделить на чанки и загружать область вокруг игрока.

План:
- отдельные игровые чанки улиц и кварталов;
- LOD для зданий, деревьев, машин и декора;
- occlusion culling для закрытых кварталов;
- статическая геометрия и объединение повторяющихся объектов там, где это безопасно;
- GPU instancing для одинаковых объектов;
- отдельные упрощённые коллайдеры вместо детальных render meshes;
- baked lighting для неподвижной архитектуры и ограниченные realtime lights;
- сжатые текстуры и контролируемые размеры текстур;
- пул объектов для трафика и эффектов;
- контроль количества материалов и draw calls.

Сначала создаётся компактный игровой район и проверяется физика. Затем город расширяется блоками. Большая карта без LOD, потоковой загрузки и профилирования приведёт к просадкам FPS и памяти.

## 5. Реалистичная машина и лицензии

В репозитории пока **нет лицензированной реалистичной 3D-модели автомобиля**. В первой сцене создаётся только временное тестовое шасси из примитивов, чтобы проверить колёса и физику. Оно не должно выдаваться за финальную машину.

Для финальной модели нужны:
- отдельные объекты четырёх колёс;
- правильный масштаб и pivot;
- салон, стёкла, фары и материалы;
- разумная топология и несколько LOD;
- проверенная лицензия, разрешающая включение модели в распространяемую игру.

Не использовать извлечённые из коммерческих игр модели и файлы без ясных прав. Для каждой модели сохранить страницу источника и условия лицензии. При необходимости сделать отдельные low-poly collision meshes.

Ни одна модель из этого списка пока не импортирована в репозиторий. Карточка магазина не заменяет техническую проверку самого архива. Финальный выбор делается после импорта: проверить pivots, scale, wheel hierarchy, LOD, draw calls, текстуры и FPS на устройстве. Условия Unity Asset Store EULA нужно соблюдать; нельзя выкладывать исходный пакет отдельно от игры.

Первая версия использует экранные удерживаемые кнопки: поворот влево/вправо, газ, тормоз и ручной тормоз. Следующие улучшения:
- аналоговый руль или виртуальный джойстик;

Камера от третьего лица уже предусмотрена в тестовой сцене. Камера салона требует корректной модели салона и точек камеры.

## 8. Сборка с телефона через GitHub Actions

Unity Editor не запускается как обычный Android-редактор на телефоне. Поэтому телефон используется для управления репозиторием и workflow, а компиляция выполняется на runner GitHub Actions через GameCI.

GameCI требует Unity license. По актуальной инструкции GameCI для Unity Personal нужно создать файл лицензии `.ulf` через Unity Hub на доступном компьютере, а затем добавить три GitHub Actions secrets: `UNITY_LICENSE`, `UNITY_EMAIL` и `UNITY_PASSWORD`. После копирования файла следует выйти из Unity Hub, чтобы освободить Personal seat. Это одноразовая настройка для CI. Только с Android-приложения GitHub/ChatGPT надёжно выполнить официальный процесс создания .ulf нельзя; можно одолжить компьютер на короткое время.

Официальные источники:
- GameCI activation: https://game.ci/docs/github/activation/
- GameCI builder: https://game.ci/docs/github/builder/
- GameCI getting started: https://game.ci/docs/github/getting-started/

В репозитории созданы два workflow:
- `.github/workflows/unity-android.yml` — сборка APK.

Пока secrets `UNITY_LICENSE`, `UNITY_EMAIL` и `UNITY_PASSWORD` не добавлены, сборка Android не может считаться готовой. Даже успешная компиляция не подтверждает отсутствие игровых ошибок: APK необходимо установить на физический телефон и проверить.

## 11. Этапы разработки

**Этап A — техническая основа:** добиться успешной сборки APK, проверить запуск сцены и базовое управление.

**Этап B — автомобиль:** получить легально используемую качественную 3D-модель, настроить pivots, колёса, подвеску, тормоза, материалы, свет и камеры.

**Этап C — физика:** настроить ускорение, торможение, сцепление, заносы, устойчивость и столкновения по тестовым сценариям.

**Этап D — городской район:** создать визуально качественный район, дорожные знаки, тротуары, освещение, окружение и оптимизированные коллайдеры.

**Этап E — интерфейс и звук:** главное меню, гараж, настройки, HUD, аудио и вибрация.

**Этап F — расширение:** потоковая загрузка районов, трафик, события, миссии, прогресс и дополнительные автомобили.

Каждый этап должен иметь проверяемый результат. Не считать функцию готовой только потому, что для неё написан C#-скрипт.
